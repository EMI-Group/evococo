# Evaluation

## Intent
Benchmark EvoX algorithms generated by EvoCoCo. Three public CLI entry points
(`run_*.py`) drive the benchmark protocols (migration reliability, optimization
fidelity, computational scaling); each spawns isolated single-trial worker
processes (`_*_trial.py`) so a failing algorithm cannot corrupt remaining runs.
The `.m` files are MATLAB/PlatEMO reference scripts (do NOT lint them as Python).

## API Surface
Public entry points (all take `--help`; run from repo root; torch/evox required
for real runs):

- `run_migration_reliability_benchmark.py` — syntax/static/exec/optimization
  checks on generated `.py` files. Flags: `-d/--dir` (required), `--workers`
  (default 8). Writes `benchmark_report.json` into `--dir` (schema:
  file/syntax/static/exec/optim/final_igd/exec_time). Uses `backend.executor`.
- `run_optimization_fidelity_benchmark.py` — repeated IGD trials per
  algorithm/problem/seed; summarizes coverage + IGD stats. Flags:
  `--algorithm-dir` | `--algorithm-file`, `--algorithms`, `--suite`
  (DTLZ|WFG|LSMOP|MaF|all, default DTLZ), `--problems`, `--runs` (21),
  `--seed-base`, `--pop-size` (100), `--generations` (100), `--objectives` (3),
  `--execution` (eager|compile), `--device` (cuda|cpu), `--gpu` (0),
  `--timeout` (3600), `--output-dir`, `--reference-csv`,
  `--absolute-tolerance` (0.10), `--relative-tolerance` (2.0),
  `--minimum-coverage` (0.80). Writes `trials.csv` + `summary.csv`
  (resumable: successful trials are skipped on re-run).
- `run_computational_scalability_benchmark.py` — DTLZ3 population/dimension
  scaling with torch.compile + optional PlatEMO speedup. Flags:
  `--algorithm-dir` | `--algorithm-file`, `--algorithms`, `--scaling`
  (population|dimension|pop|dim), `--sizes`, `--fixed-dimension` (100),
  `--fixed-population` (1000), `--objectives` (3), `--executions`
  (compile|eager|both, default compile), `--repeats` (11), `--generations`
  (100), `--warmup` (5), `--seed-base`, `--device`, `--gpu`, `--timeout`
  (3600), `--recompile-limit` (512), `--output-dir`, `--platemo-csv`,
  `--platemo-timeout-seconds` (10800). Writes `trials.csv` + `summary.csv`.

Internal workers (invoked by the entry points; flags are their contract):
`_fidelity_trial.py` (module_prefix `evococo_fidelity_`, prints
`EVOCOCO_FIDELITY_RESULT=` JSON) and `_scaling_trial.py` (module_prefix
`evococo_eval_`, prints `EVOCOCO_TRIAL_RESULT=` JSON).

Shared module `_common.py`: constants (default paths, RESULT_PREFIX_*),
entry-point helpers (`positive_int`, `discover_algorithms`, `check_cuda`,
`read_rows`, `append_row`, `run_worker_process`), worker helpers
(`load_algorithm_class`, `setup_torch_device`, `instantiate_algorithm`,
`finite_fitness_rows`).

`_benchmark_problems.py`: problem suites/dimensions and `create_problem`
(fidelity runner + worker share it).

## Constraints
- CLI flags, defaults, help text, trials.csv/summary.csv column order+values,
  `benchmark_report.json` schema, and the worker result-print line are PUBLIC
  contracts (users/CI depend on them) — do not change.
- Do not change benchmark semantics or default parameters.
- No new dependencies; keep files under ~1000 lines.
- `_common.py` sections: entry-point helpers vs worker helpers — keep the split.
- Only `evaluation/` is in scope; `backend/` and repo root are out of scope.

## Routing Table
None — flat directory; work is done in this node directly.

## Known Issues
- `backend/config.py` prints a warning emoji at import time, which raised
  `UnicodeEncodeError` on GBK Windows consoles (broke even `--help` for the
  migration benchmark). Mitigated in-script with a guarded UTF-8
  `sys.stdout/stderr.reconfigure(...)` before the backend import; the backend
  print itself is out of scope.
- This dev environment has no torch/evox installed — real benchmark runs and
  `check_cuda` require the GPU environment.

## Test Strategy
- Cheap (no GPU): `python -m compileall -q evaluation`; `python -m ruff check
  evaluation` (must be clean); `--help` on all entry points/workers; argparse
  validation (`--gpu -1`, missing required flags → exit 2); torch-free
  functional tests of `_common.py` (CSV round-trip, `run_worker_process`,
  `load_algorithm_class` with a fake evox module).
- Needs torch/evox (GPU): actual trials. README.md documents small smoke runs
  (`--runs 2 --generations 10` for fidelity; `--sizes 100 --repeats 1 --warmup 1
  --generations 3` for scaling; `--device cpu` is a functional CPU smoke).
- PlatEMO baselines are generated by the `.m` scripts (MATLAB), not by Python.
